# Создание стенда падает на временных сбоях Selectel без повтора

## Что не так
`vrata-stage up` считает любую ошибку провайдера окончательной. Сервер переходит в `ERROR`, стенд — в `failed`, и повторить создание можно только вручную: `release`, затем новый `acquire`. На такие сбои уходят лишние десятки минут, если никто не следит за журналом, а сессия, ждущая стенд, получает отказ.

## Почему всплыло
2026-10-25 сервер `24c6dfa8` стенда платформы через 5,5 минуты после создания ушёл в `ERROR` с ответом Nova: «Build of instance … aborted: Failed to allocate the network(s), not rescheduling». В сети стенда при этом не было висящих портов, плавающий IP был свободен; повтор через минуту создал сервер без ошибок.

## Почему не сейчас
Переключение стендов завершено; повтор — улучшение инструмента, а не блокер.

## Что сделать
Собрать список ответов провайдера, которые означают временный сбой (выделение сети, нехватка ресурсов в пуле, transport-ошибки API), и решить, сколько раз и с какой паузой `up` повторяет создание сам, прежде чем перейти в `failed`.

## Актуальность 2026-10-26
В `tools/vrata-stage.py` есть повтор HTTP-вызовов API (`call`, четыре попытки для GET/PUT/DELETE), но сервер в `ERROR` после создания по-прежнему переводит стенд в `failed` без повтора.

## Сделано 2026-10-26: повторы gh

26.10 создание стенда трижды падало на `gh_failed:run list --repo:error connecting to api.github.com`, пока хук ждал уже запущенный workflow. Bootstrap и активация на GitHub при этом шли дальше, но стенд оставался в `failed`.

- `GitHub.gh` повторяет сетевые и серверные сбои GitHub (до пяти попыток, паузы 5–40 с), отказы не повторяет.
- `dispatch` не повторяет `workflow run` вслепую: после потерянного ответа ищет запуск по request id (девять опросов, около трёх минут) и запускает заново с тем же id, только если запуск так и не появился.
- Сбой опроса в ожидании пропускается до общего дедлайна.

Сервер Selectel в `ERROR` после создания («Failed to allocate the network(s)») по-прежнему переводит стенд в `failed` без повтора: пункт остаётся открытым для этой части.

## Сделано 2026-10-26: повтор сборки сервера

26.10 сборка сервера ещё раз упала с «Failed to allocate the network(s)». Теперь `up` удаляет свой сервер в `ERROR` и собирает его заново, всего до трёх сборок с паузами 30 и 60 с. Повторяются только временные ошибки Nova: «Failed to allocate the network», «No valid host was found» и «Exceeded maximum number of retries». Квоты, образ и flavor сразу переводят создание в `failed`. Плавающий IP привязывается только к собранному серверу. Пункт закрыт.
