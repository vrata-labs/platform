# Room-state хранит состояние удалённой комнаты под тем же roomId

## Что не так

Room-state держит комнаты и медиа-объекты только в памяти и никогда не удаляет комнату из Map.
При удалении комнаты API не сообщает room-state об этом: очищаются только медиа-объекты документов.
Если комнату создать заново с тем же roomId, участники новой встречи попадают в прежнее состояние room-state:
медиа-объекты, поверхности и привязки исполнителя удалённой встречи. Проверка привязки исполнителя
(bindings/verify) тоже опирается на это прежнее состояние, поэтому может разрешить выдачу медиа-гранта
исполнителю объекта удалённой встречи в новом поколении комнаты.

## Почему всплыло

Независимая проверка дизайна S3b-3 указала, что room-state не знает поколения комнаты;
по коду подтверждено отсутствие очистки при удалении (apps/api/src/index.ts, apps/room-state/src/index.ts).

## Почему не сейчас

Медиа-граница S3b-1 уже разводит поколения по именам LiveKit-комнат, а S3b-3a выселяет исполнителей
выведенных поколений. Изоляция состояния room-state — отдельное изменение протокола между API и room-state.

## Что сделать

Передавать room-state поколение комнаты (media_incarnation) при входе и в проверках привязки
либо сбрасывать состояние комнаты в room-state при её удалении; проверить пересоздание с тем же roomId
на объектах, поверхностях и исполнителе.
