# До входа на floor 2 не видны настройки шаблона комнаты

## Что не так

Перед экраном входа runtime читает манифест комнаты анонимно (fetchPublicTemplateSettings),
чтобы показать настройки шаблона: «входить с выключенным микрофоном», область заметок.
На floor 2 граница identity отклоняет анонимное чтение привязанной комнаты (409), и
настройки остаются неизвестными. Начальное значение галочки выключенного микрофона берётся
из общей (не комнатной) сохранённой настройки, а без неё — включено. Показанный выбор
сохраняется и после входа побеждает шаблон; остальные настройки шаблона, например область
заметок, применяются после входа. Теряется начальный выбор комнаты: где по шаблону
микрофон открыт, гость обычно входит с выключенным.

## Почему всплыло

Независимая проверка исправлений floor 2 после активации на общем staging указала на
анонимный запрос в apps/runtime-web/src/template-preferences.ts.

## Почему не сейчас

Показанный пользователю выбор соблюдается: микрофон не включается вопреки галочке. Применять
шаблон после входа поверх показанной галочки нельзя — это может неожиданно открыть
микрофон. Нормальное решение требует отдельного проектирования границы.

## Что сделать

Выдать до входа только публичные настройки шаблона публичной комнаты отдельным
ответом на границе identity (без участников, токенов и приватных данных) либо
показывать экран входа после получения сессии. Проверить на floor 2 комнату с
открытым микрофоном по умолчанию и комнату presentation с выключенным.

## Стоимость и эффект

Небольшой новый ответ API и правка экрана входа, плюс проверка границы. Возвращает
настройки комнаты до входа на floor 2.

Анонимное чтение манифеста по-прежнему в `apps/runtime-web/src/template-preferences.ts:35` (`fetchPublicTemplateSettings`); floor 2 работает на staging и в production портала — затронут каждый гость публичной комнаты.

## Сделано 2026-10-27

Ночной план 2026-10-26-night-prejoin-template-defaults. Влито в main в #149, поставлено на stage 2026-10-27.

- API: анонимный GET /api/rooms/:roomId/prejoin-settings (apps/api/src/room-prejoin-settings.ts) отдаёт только
  настройки шаблона (layout, notes, audio, presentation) комнаты, куда гость входит по ссылке: public или unlisted,
  открытой гостям, не отключённой и не управляемой порталом. Такая комната без шаблона получает settings: null.
  Приватная, закрытая для гостей, отключённая, управляемая порталом и несуществующая комната получают прежний
  отказ границы identity.
- Runtime: fetchPublicTemplateSettings узнаёт floor по /health и на floor 2 читает этот ответ, на floor 1 — манифест,
  как раньше. Если ответа нет или он отклонён, галочка «входить с выключенным микрофоном» включена; побеждает только
  выбор пользователя, сохранённый для этой комнаты, общая настройка из другой комнаты микрофон не открывает.
  Выбор, сделанный при неизвестном шаблоне, остаётся за этой комнатой и не переписывает общую настройку.
- e2e reference meeting проверяет снятую галочку на экране входа; на staging этот сценарий в Staging Extended.

- Проверка на staging floor 2 (комната meeting с открытым микрофоном и presentation с выключенным) в эту работу не
  входила: план ограничен кодом и тестами. В плане по бэклогу — пункт 14. Проверено 2026-10-27 на stage floor 2
  с ea933e5: presentation — галочка стоит (Staging Deploy, run 40513489925), meeting — снята (Staging Extended,
  run 40526091104).
- Комнаты портала (managed) входят только по grant, поэтому новый ответ их не раскрывает: их гости на floor 2
  по-прежнему видят галочку «входить с выключенным микрофоном». Нужен ответ, проверяющий grant до входа, либо экран
  входа после обмена grant. В плане по бэклогу — пункт 16.
