# Приватные сцены: восстановление в GitVerse и поставка из Selectel S3

## Цель

Восстановить найденный локальный снимок приватных сцен в приватном репозитории организации GitVerse `vrata-labs` (уточнение D-003). Поместить существующие файлы сцен в Selectel S3 и перевести staging на загрузку закреплённого готового пакета из S3, без обращения к репозиторию сцен при развёртывании.

Выбранная схема: **GitVerse — хранение и развитие репозитория; приватный S3 — источник готовых релизов; платформа — раздача файлов браузеру**. Перенос не включает повторный экспорт моделей.

- Исправление старых моделей, текстур и материалов, изменение рассадки, аватаров и качества сцен.
- Прямое скачивание браузером из S3, публичный S3-бакет, CDN, новый сервис хранения или универсальный реестр артефактов.
- Замена встроенного SeaweedFS и настроек `MINIO_*`, хранилища плагинов, пользовательских загрузок или их storage fingerprint.
- Production, очистка старых релизов S3, ротация посторонних ключей, обход ограничений GitHub и автоматические обращения за доступом.

## Предпосылки и ограничения

1. Согласованная организация — `vrata-labs` (D-003). HTTP 401 официального API без токена и веб-404 не доказывают отсутствия организации. Нужны авторизованная проверка членства/прав и пустое приватное назначение; при отсутствии прав остановиться, не запрашивать их от имени пользователя.
2. Имя нового репозитория по умолчанию — `vrata-scene-assets-private`. Если оно занято, проверить существующий репозиторий и согласовать несовпадение; не применять force/mirror к чужому содержимому.
3. Размеры крупнейших файлов и действующие лимиты GitVerse проверяются перед push. Не переводить файлы в LFS без необходимости. Если GitVerse требует LFS, сначала установить поддерживаемый Git LFS, проверить квоту и сохранить исходные байты; это отклонение записать в журнал.
4. S3-проект, пул и endpoint выбираются по фактическому доступу. Зона сервера `ru-2c` не определяет S3-пул. Keystone-токен Selectel не заменяет S3 Access Key ID/Secret Key.
5. Права на публичное распространение SenseTower-сцен не подтверждены. Репозиторий и S3 остаются приватными. Существующую доступность сцен через маршруты внутреннего стенда не расширять.
6. Предыдущий admin merge PR #158 был разовым разрешением, не разрешением сливать этот план или будущие изменения в обход защиты. Поставка workflow в `main` проходит обычное согласование; при блокере нужен отдельный выбор пользователя.
7. Исходный каталог временный: прежде любых преобразований сохранить независимую защищённую копию, содержащую `.git`, tracked files и метаданные shallow-снимка. Место по умолчанию — `~/.local/share/vrata/private-scene-recovery/0a3b492e788bad82bf20a92476a628bf30c6dfbe/`, каталог 0700, файлы архива/инвентаря 0600. Проверить свободное место; существующую копию не перезаписывать. Не удалять исходник после переноса автоматически.
8. Платформенную часть выполнять в отдельной узкой infra-ветке от актуального `origin/main`, не перенося в неё runtime-изменения T17. Сначала обычным PR поставить S3 workflow/helper в `main`, затем влить этот `main` обратно в T17 и проверить новый итоговый SHA. Нельзя сливать PR #157 целиком только ради bootstrap.

## Выбранный подход

### Репозиторий и происхождение

Создать отдельный чистый staging-каталог из текущих отслеживаемых файлов, а не редактировать `.git/shallow`. Новый root-коммит в GitVerse содержит тот же снимок; отдельная запись восстановления указывает старый remote, SHA, tree SHA и отсутствие предшествующей истории. Новая запись не подменяет исходные LICENSES.

Сравнение при контрольном клонировании — по исходному инвентарю: файлы восстановления могут быть добавлены отдельно, но ни один исходный файл не теряется и не меняется. Git push выполняется только в новое пустое приватное назначение, без слепого `--mirror`.

### Готовый релиз в S3

Один небольшой helper `tools/private-scene-release.py` с командами `pack`, `publish`, `fetch` и тестами. Использовать установленный AWS CLI; для CI зафиксировать доступную поддерживаемую версию. Новый сервер или постоянно работающий сервис не нужен.

Локальная реализация helper и integration продолжается через стандартный S3 API/AWS CLI независимо от тайм-аута панели Selectel (D-007). Реальная публикация и k03 требуют отдельной положительной проверки доступа из Task 1; ограничения приватности и reader/writer сохраняются.

- В пакет входит существующее дерево `assets/manifest.json` и `assets/scenes/` целиком, без `.git`, ключей и посторонних каталогов. Все 28 записей сохраняются; известные недостатки legacy-сцен остаются в приватном отчёте происхождения. Приёмка загрузки на стенде относится к его 13 используемым сценам.
- Упаковка не пересобирает GLB/GLTF/FBX и не переписывает `scene.json`. Инвентарь фиксирует относительный путь, длину и SHA-256 каждого файла.
- Архив имеет детерминированный порядок/метаданные. Релиз содержит descriptor с версией формата, `assetSha`, ключом архива, его размером и SHA-256, контрольной суммой инвентаря и происхождением снимка.
- `assetSha` остаётся 40-символьным Git SHA; SHA-256 архива — отдельные 64 hex. Схему accepted-release менять не нужно. Новый релиз использует SHA восстановленного GitVerse-снимка.
- Ключ descriptor однозначно получается из binding: `private-scenes/releases/<assetSha>/release.json`. Ключ архива внутри descriptor: `private-scenes/releases/<assetSha>/<archiveSha256>/bundle.tar.gz`. Descriptor также неизменяем: его нельзя перенаправить на другой архив. Никаких `latest`, mutable `main` и адресов с секретами.
- Архив загружается первым, descriptor — последним. Повтор тех же байтов допустим; другой контент для уже опубликованного release ID отклоняется. Неизменяемость обеспечивается проверкой существующего объекта и условной записью, если она поддержана выбранным пулом; versioning не подменяет эти проверки. Если атомарная условная запись недоступна, до публикации исключить одновременных писателей, а не заявлять неподтверждённую гарантию.
- Writer может публиковать только в выделенный префикс; reader — читать закреплённые объекты. Удаление релизов не входит в права обычного деплоя. ETag не считается SHA-256.

### Деплой и откат

Вместо `Checkout pinned private assets` GitHub Actions скачивает архив из S3 read-only ключом, проверяет размер/хеш, безопасно распаковывает во временный source и передаёт его на хост существующим SSH-шагом. S3-ключи не нужны на staging-хосте, GitVerse-токен не нужен в deployment workflow.

До шага `Sync workspace to deploy SHA` сохранить S3 helper и его минимальные зависимости из версии workflow в `RUNNER_TEMP` рядом с существующими rollback helpers. После checkout старого кандидата вызывать эту закреплённую копию: старые runtime-коммиты нового helper не содержат. Для исторического binding descriptor находится по `assetSha`, даже если в старом checkout отсутствует release lock.

Закрепление нового кандидата хранится в небольшом `infra/docker/private-scene-release.lock.json`: `assetSha`, ключи descriptor/архива, размеры и SHA-256, без credentials. Endpoint/бакет — настройка окружения. Для уже связанного image SHA приоритет имеет его сохранённый binding, а не новый lock.

Для старых bindings нельзя заменять `assetSha` новым SHA восстановленного репозитория. Совместимый descriptor под прежним `assetSha` допустим только при доказанном совпадении инвентаря старого принятого релиза. Найденный снимок `0a3b492…` позволяет готовить такую проверку, но не доказывает тождество любого другого исторического релиза. Если его bytes/descriptor не восстановлены — откат на него блокируется явно, без догадок.

После fetch используется прежний `staging-remote-release.py --source` и `staging_scene_files.py`: проверка полноты каталога, immutable snapshot, блокировка операции, атомарный active, принятие JSON только после gate, retention current/previous/Wave 2 и версий из room URLs. Никакого fallback к checkout сцен.

Текущие URL сцен платформы сохраняются: часть маршрутов Hall/BlueOffice сейчас использует `state.<host>`, а не app origin. Менять это ради S3 не требуется. Браузер не получает S3 credentials/presigned URLs и не обращается к S3. Публичные сцены и их отдельная CI-валидация не затрагиваются.

## Тест-план

1. **Unit:** deterministic pack; отдельный source SHA/archive SHA-256; schema/path validation; корректная передача ключей без печати; неизменность release IDs и исходных файлов.
2. **Integration:** fake S3 и настоящий отдельный тестовый префикс в Selectel; reader/writer permissions, 403/404, multipart/ETag, обрыв загрузки, неверные размер/digest/inventory, опасная распаковка, повтор и конфликт. Не портить опубликованный рабочий релиз ради негативного теста.
3. **Rollout/recovery:** текущие тесты scene snapshot/accepted-release и A -> B -> failed gate -> A; свежая среда без Git-сцен; старый binding без подмены; current/previous/Wave 2/сохранённые room URLs; backup со сменой acceptance.
4. **Local:** `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`; отдельный infra PR — полный штатный e2e доступной версии, итоговый T17 — `pnpm test:e2e:gpu --workers=1 --retries=0` и обязательный `pnpm test:e2e:private-assets` с восстановленным пакетом и прежними assertions.
5. **CI/staging:** текущий CI и Docker exact SHA; новый штатный bootstrap + полный catalog gate; полный staging suite и `pnpm test:e2e:staging-extended` после deploy, реальные сетевые ответы и scene diagnostics. `loaded` не заменяет визуальную приёмку качества.

## Риски и снижение

- **Неполная история:** новая история согласована; оригинал сохраняется отдельно, существующие коммиты не выдаются за полный clone.
- **Ограничения GitVerse/LFS:** измерить размеры до push; не удалять большие файлы и не переписывать исходный clone ради лимитов.
- **Утрата или утечка сцен:** private repository/bucket, отдельные reader/writer, запрет анонимного S3 и отсутствие binaries в платформе; секреты не попадают в URL, логи, descriptor и backup отчёты.
- **Смешение релизов:** binding по image SHA не менять; content digest проверять независимо; mutable `latest` исключён; старые descriptors не удалять.
- **Неполный старый rollback:** подтверждать только восстановленные bytes; неизвестную старую версию не заменять похожей. Наличие descriptor без архива недостаточно.
- **Сбой S3:** конечный download timeout и явный отказ до rollout; уже принятый локальный snapshot продолжает работать. Новое развёртывание не объявляется успешным.
- **Изменение workflow только в ветке:** сначала согласованная поставка в `main`, затем новый хост; прежнее разрешение admin merge не переносится.
- **Объём около 410 МБ:** потоковые операции, контроль места под download/extract/snapshot, ограниченное число локальных копий. Никаких новых rebuild моделей.

## Откат

До acceptance ошибка fetch/проверки оставляет прежние контейнеры, active snapshot и room URLs неизменными. При провале gate действует существующий rollback на предыдущую принятую связку image/assets.

После атомарной публикации accepted-release ошибки метаданных устраняются существующим explicit repair; нельзя откатить контейнеры, оставив новую принятую запись. Нужные previous/Wave 2/S3-релизы сохраняются.

Откат внедрения не должен возвращать обязательный GitHub private checkout: он заведомо недоступен. Рабочая точка возврата — прежний проверенный snapshot или его точный S3 release. Новые GitVerse/S3 данные и исходную копию автоматически не удалять.
